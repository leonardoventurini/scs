# Release SCS 0.2.0

## Outcome

Publish the current unreleased changes as SCS `0.2.0` through the established
GitHub Release workflow. The version signals that the agent-facing MCP read
inventory changes from seven specialized tools to `query_code`.

## Scope and contracts

- Set Python metadata, runtime, Rust workspace dependencies, and both lockfiles
  to `0.2.0`. Move the unreleased changelog entries into a dated `0.2.0`
  section.
- Release the exact `main` commit that passes local verification and GitHub CI.
- Publish the existing macOS and Linux wheels, source distribution, constraints,
  installer, SBOM, checksums, and provenance through the tag workflow.
- Keep the query contract in
  [unified-query-orchestration.md](2026-09-22-unified-query-orchestration.md)
  and the caller migration in
  [query-code-migration.md](../docs/query-code-migration.md) authoritative.
  This release adds no further API or persisted-data change.

## Acceptance criteria

- Every version identity and generated package lock agrees with `v0.2.0`.
- The published release comes from the verified `main` commit, and macOS,
  Linux, and supply-chain CI pass before the annotated tag is pushed.
- The tag workflow passes, and the public release provides every documented
  asset with matching `SHA256SUMS` entries.
- A clean installation of a published wheel reports `0.2.0` and exposes the
  five-tool MCP inventory described by the migration guide.

## Verification plan

- Run the existing release identity test before and after the bump, the version
  checker, and `just verify` locally.
- Inspect the GitHub CI run for the release commit before tagging; inspect the
  tag workflow and published assets after tagging.
- Verify downloaded assets against checksums and run a clean installed-wheel
  smoke test on an available platform. The release workflow also smoke-tests
  both wheels on hosted runners.

## Risks and recovery

The MCP change requires hard-coded callers to migrate. Existing persisted
indexes need no format migration. Before the tag, a failed gate blocks release.
After publication, assets and tags are immutable; correction uses a new version.
Installing the previous compatible release is the rollback path.
