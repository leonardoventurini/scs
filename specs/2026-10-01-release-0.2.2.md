# Release SCS 0.2.2

## Outcome and scope

Publish the approved [uninstall command](2026-10-01-uninstall-cli.md) as SCS
`0.2.2` through the established GitHub release workflow. The user's instruction
to release authorizes pushing the verified release commit and annotated tag and
publishing release notes. The active installation is not part of this rollout.

Update Python metadata, runtime, Rust workspace identities, both lockfiles,
changelog, and installation examples together. No further API, persisted-data,
dependency, workflow, or artifact-format change is intended.

## Acceptance criteria and verification plan

1. Every release version agrees with `v0.2.2`; execute the existing release
   identity tests before and after preparation, the version checker, and
   `just verify`.
2. The tagged commit is reachable from `main` and passes hosted macOS, Linux,
   and supply-chain CI before tagging; inspect exact commit and run results.
3. The tag workflow publishes both platform wheels, source distribution,
   constraints, versioned installer, SPDX SBOM, and checksums with provenance;
   inspect workflow results and verify downloaded asset checksums/attestation.
4. A disposable installation from published assets reports `0.2.2`, exposes
   `uninstall --purge`, and can uninstall itself with preservation and purge;
   exercise the installed wheel on available local macOS without stopping the
   active instance. Hosted Linux wheel smoke testing complements local coverage.
5. Release notes describe state preservation, optional cleanup, retained lock
   files, uv availability, and manual MCP registration removal.

## Recovery and risks

Before tagging, failures block release. Published assets and tags are immutable;
corrections use a new version. Reinstall `0.2.1` to roll back the executable;
there is no state migration. Purged state requires backup restoration.
Verification uses disposable installation/data/runtime directories. No core
service or active SCS instance is stopped.

## Verification results

All five acceptance criteria passed. The stable public release is
[SCS 0.2.2](https://github.com/leonardoventurini/scs/releases/tag/v0.2.2).

1. **Version identity and local gates — passed.** The existing release tests
   passed before and after preparation (2 tests each).
   `python3 scripts/check-release-version.py v0.2.2`,
   `cargo check --workspace --offline`, and `git diff --check` passed.
   `just verify` passed after preparation and test stabilization: strict
   Basedpyright and Ruff, 422 Python tests, 87.28% branch-aware coverage, and
   108 Rust tests. Lockfiles changed only first-party versions.
2. **Main CI and tag — passed.**
   [Main CI](https://github.com/leonardoventurini/scs/actions/runs/36933752963)
   passed macOS, Linux, and supply-chain jobs on `cf6712a`. The signed annotated
   `v0.2.2` tag resolves to that exact commit and is reachable from `main`.
   `git verify-tag v0.2.2` passed.
3. **Publication and integrity — passed.** Every job in the
   [release workflow](https://github.com/leonardoventurini/scs/actions/runs/36934963810)
   passed, including both wheel installation smoke tests. Seven public assets
   provide the two wheels, source archive, constraints, installer, SPDX SBOM,
   and `SHA256SUMS`. Downloading all assets and running
   `shasum -a 256 -c SHA256SUMS` verified all six payload files. Both wheel
   attestations passed `gh attestation verify` with the expected repository,
   `--source-digest cf6712abe4afda8c814a279ea3b7e7c5a9f03ff4`,
   `--source-ref refs/tags/v0.2.2`,
   `--signer-workflow leonardoventurini/scs/.github/workflows/release.yml`, and
   `--deny-self-hosted-runners` enforced. Provenance identifies this release run.
4. **Published installation and self-uninstall — passed on macOS.** The
   checksum-verified public installer was executed twice in disposable uv
   tool/data/runtime directories, with the active executable excluded from
   PATH. Both installations reported `0.2.2`, imported the native extension,
   and exposed `uninstall --purge`. Separate installed Python processes invoked
   CLI main with `Path.home()` patched to the disposable user root. Preservation
   retained all sentinels and configuration; purge removed them and retained
   coordination lock files. Both removed their own tool environments and
   launchers despite a deliberately changed `UV_TOOL_DIR`, preserved MCP
   configuration, and printed manual removal instructions. All disposable
   installations were cleaned up; the active instance was untouched.
5. **Release notes — passed.** The published notes describe preservation,
   purge, retained lock files, uv availability, manual MCP removal, and recovery.
   GitHub identifies `v0.2.2` as the latest stable release, not a draft/prerelease.

## Plan deviation and limitations

Initial main CI on `660b2bf` exposed an existing macOS test scheduling race:
`test_unattached_startup_grace_keeps_active_jobs_observable` assumed a
thread-pool job check completed within a 15 ms sleep. Commit `cf6712a` replaced
that assumption with a bounded thread-safe observation event, kept simulated
work active through socket-backed health verification, then verified shutdown.
Production behavior did not change. The 13 service-route integration tests and
all local/hosted gates subsequently passed.

A separate Linux public-installer/self-uninstall run was not executed locally;
hosted Linux CI and installed-wheel smoke testing passed. Local public-installer
checks used absent-daemon shutdown; the full suite covers live shutdown and
cancellation separately. The active workstation was not upgraded. Reinstall
`0.2.1` to roll back code; deleted state requires a backup.

Review the version/lockfile changes, the startup-grace test synchronization,
then the published notes and this verification evidence. No public API, schema,
dependency, workflow, or artifact-format change beyond the approved uninstall
feature was introduced.
