# Release SCS 0.2.2

## Outcome and scope

Publish the approved [uninstall command](2026-10-01-uninstall-cli.md) as SCS
`0.2.2` through the established GitHub release workflow. The user's instruction
to release authorizes pushing the verified release commit and annotated tag and
publishing release notes. The active installation is not part of this rollout.

Update Python metadata, runtime, Rust workspace identities, both lockfiles,
changelog, and installation examples together. No further API, persisted-data,
dependency, workflow, or artifact-format change is intended.

## Acceptance criteria and verification plan

1. Every release version agrees with `v0.2.2`; execute the existing release
   identity tests before and after preparation, the version checker, and
   `just verify`.
2. The tagged commit is reachable from `main` and passes hosted macOS, Linux,
   and supply-chain CI before tagging; inspect exact commit and run results.
3. The tag workflow publishes both platform wheels, source distribution,
   constraints, versioned installer, SPDX SBOM, and checksums with provenance;
   inspect workflow results and verify downloaded asset checksums/attestation.
4. A disposable installation from published assets reports `0.2.2`, exposes
   `uninstall --purge`, and can uninstall itself with preservation and purge;
   exercise the installed wheel on available local macOS without stopping the
   active instance. Hosted Linux wheel smoke testing complements local coverage.
5. Release notes describe state preservation, optional cleanup, retained lock
   files, uv availability, and manual MCP registration removal.

## Recovery and risks

Before tagging, failures block release. Published assets and tags are immutable;
corrections use a new version. Reinstall `0.2.1` to roll back the executable;
there is no state migration. Purged state requires backup restoration.
Verification uses disposable installation/data/runtime directories. No core
service or active SCS instance is stopped.
