# Release SCS 0.1.15

Status: shipped

Project: `scs`

Project root: `/Users/leonardo/Repositories/scs`

## Outcome

Publish the evidence-driven agent workflow improvements as SCS `0.1.15` using
the existing GitHub release process.

## Scope and contracts

- Move the current unreleased changes into the `0.1.15` changelog section.
- Update Python, Rust workspace, runtime, lockfile, and installation-example
  versions together.
- Preserve the release workflow, artifact formats, installer behavior, public
  APIs, and persisted graph formats.
- Push the release commit to `main` only after local release gates pass.
- Require green macOS, Linux, and supply-chain CI before tagging.
- Create and push annotated tag `v0.1.15`, then require every release job to
  pass before accepting the publication.

## Risks and recovery

An incorrect version identity would produce mismatched artifacts; the release
version checker prevents that. A failing prerequisite CI run blocks tagging.
A failing tag workflow blocks acceptance and must be corrected with a new patch
version if immutable assets were published. Before publication, rollback is a
normal revert of the release-preparation commit.

Metrics state is separate from graph and job state. This release has no graph
data migration and older installations remain the rollback path.
