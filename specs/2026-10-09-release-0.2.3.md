# Query quality and SCS 0.2.3

## Outcome and approved scope

Improve query routing and bounded inspection evidence, expand evaluation with
natural goals and missing anchors, document efficient readiness checks, publish
0.2.3, and upgrade the local installation. The user approved option a and the
release and upgrade. Existing unified-query contracts remain authoritative.

Historical CLI use found ineligible routing in 35 of 155 returned queries outside
SCS development. Inspection currently sorts opaque IDs before truncation.
These are optimization signals, not a claim that every partial result failed.

## Design and compatibility

Share eligibility rules between classifier requests and execution. Offer only
eligible choices through the existing generic choice API and expand its answer
to the public seven-entry probability vector with zeroes for excluded choices.
Preserve the conservative DISCOVER fallback and exactly one classifier decision.
An initial live experiment showed that descriptions alone still selected
unavailable REFERENCES and IMPACT choices, motivating this request constraint.

Rank declarations before containers and imports, with source position, name,
and ID as stable ties. Read file nodes in bounded native batches and retain only
the requested best nodes. Keep existing node/edge ceilings and truthful
truncation. Ranking is structural, not an additional model call.

Expand versioned evaluations without copying historical prompts. Explain that
ordinary capped results do not require reindexing; wait on a specific job after
explicit ingestion. No readiness cache is introduced.

MCP inputs, response envelopes, persisted data, security boundaries, production
dependencies, mode budgets, and external choice API shapes do not change.
No history content is stored. Cortex remains running throughout.

## Acceptance criteria and verification

1. Classifier guidance and execution agree on missing-anchor eligibility;
   invalid selections still fall back safely. Verify generated combinations,
   provider tests, and natural-goal live classification. Target under 5%
   ineligible selections on the expanded evaluation, without claiming a
   historical-production rate improvement from a synthetic sample.
2. A capped inspection returns declarations ahead of imports, deterministically,
   and preserves source aliases, edge limits, and truthful truncation. Verify
   generated native graph fixtures, integration tests, and live inspection.
3. Broader query evaluation separates truncation from degradation and reports
   routing, evidence, bytes, and latency. Run existing and expanded suites
   against an isolated updated daemon; record all gates and limitations.
4. Readiness guidance describes one initial check, explicit job waits, and
   rechecks after indexing or availability failures. Review documentation.
5. Release identities agree, local `just verify` and hosted CI pass, and immutable
   0.2.3 assets have valid checksums/provenance. Publish only the verified commit.
6. The installed public wheel reports 0.2.3 and its MCP queries use the new
   ranking while retaining existing repository registrations and configuration.
   Upgrade using the supported installer and cooperative SCS lifecycle.

## Risks and recovery

Classifier response to wording is empirical; retain fallback and record observed
accuracy. Structural ranking may change which capped symbols are returned;
unbounded inspection retains the same membership. No state migration occurs.
Before publication, gate failures block release. After publication, corrections
receive a new version; reinstall 0.2.2 to roll back the executable.

## Verification results

The fixes passed `just verify`: strict Basedpyright, Ruff, 434 Python tests,
87.31% branch-aware coverage, and 108 Rust tests. Regression tests failed before
the ranking and degradation fixes and passed afterward. Source alias membership
and existing bounded-edge integration checks passed.

Live external classification of the 17 v3 goals selected eligible workflows in
17/17 cases and the expected workflow in 16/17. The missing-anchor reference goal
selected INVENTORY rather than DISCOVER; safe eligibility is verified, while
semantic routing remains imperfect. Full isolated query evaluation, publication,
and installed-wheel verification are pending.
